# ERU · AI 동행 투자 V3

실제 과거 시세로 **이메일 인증 → 성향·코인 비율 직접 선택 → 초기 자동 매매 → 기본 가드와 논의 → 승인한 매매 실행 → 계정에 복기 보관**을 경험하는 5분 투자 시뮬레이션입니다. 초기 자금은 **1억 원**, 거래 대상은 가명 코인 4종과 현금 (이자 수익)입니다.

## 바로 실행

**[온라인에서 AI 동행 투자 테스트하기 →](https://eru-ai-investment-simulator.vercel.app)**

처음에는 이메일로 받은 인증번호를 입력합니다. **내 투자 기록 → 새 투자 시작**으로 시작하며, 작성 중인 포트폴리오 초안·진행 중인 게임·매매와 판단·대화·종료 복기를 계정에 보관합니다. 같은 이메일로 다른 기기에서도 이어볼 수 있습니다. [이메일 인증과 계정별 보관](docs/이메일인증과_계정보관.md)

[새 초기 설정 화면 열기](https://eru-ai-investment-simulator.vercel.app/?setup=1)는 인증 후 내 투자 기록으로 이동합니다. 인증 전의 비회원 게임은 삭제하지 않지만, 소유자를 확인할 수 없어 어떤 계정에도 자동 연결하지 않습니다.

2026-10-21 첫 접속 연결 장애를 복구했습니다. 새 게임은 Supabase PostgreSQL에 저장합니다. 정지된 이전 Blob 저장소의 게임은 보존 중이며 아직 이관되지 않았으므로 새 초기 설정으로 테스트해 주세요. [복구·검증 기록](docs/저장소_연결장애_2026-10-21.md)

1. **포트폴리오 유형**에서 균형형·안정형·공격형·기타의 특징을 읽고 직접 선택합니다. 기타에서는 현금·투자 비중을 직접 정합니다. AI를 호출하지 않습니다.
2. **코인과 비율**에서 네 코인의 역할·특징·위험을 읽고 투자할 종목을 체크합니다. 옆의 비율 박스에서 투자금 내 비율을 직접 입력하거나 균등 배분하고, 전체 자산 기준 비중과 금액을 확인합니다. 이 단계도 AI를 호출하지 않습니다.
3. **전체 계획 확인 → 이 계획으로 투자 시작 → 확정하고 자동 투자 시작**으로 구성·이자·기본 가드를 확인하고 승인하면 다음 일봉 시가에 초기 주문을 체결합니다. 사용자 조건 설정과 조건 상담 단계는 제거했습니다.
4. 기본 가드는 한 종목 비중 60% 초과, 확정 주봉 RSI 75 초과, RSI 30 미만이면서 현금 20% 이상, 보유 코인의 확정 일봉 10% 초과 하락을 확인합니다. 알림 후 게임 속 90일 간격과 같은 종목·주봉 중복 방지를 적용합니다.
5. 가드가 신호를 감지하면 시장을 멈추고 ERU AI와 대응을 논의합니다. 사용자 승인 매매만 실행합니다.
6. 활성 재생 300초 후 **투자 복기**에서 실제 자산 그래프의 번호나 선택 카드를 누릅니다. 당시 구성·논의·승인과 다음 일봉 체결, 매도 실현손익을 함께 확인합니다. 처음 계획 그대로 보유한 비교, 선택별 매매 여부 비교, 종목별 실현·평가손익과 AI 복기를 제공합니다. [계산 기준과 검증](docs/투자결과_복기.md)

**AI 연결:** 서버의 `OPENROUTER_API_KEY`로 OpenRouter Chat Completions API를 호출합니다. 기본 모델은 `openai/gpt-6-luna`이며 서버의 `OPENROUTER_MODEL`로 변경할 수 있습니다. 구조화 출력 지원 제공업체로만 요청하며 OpenAI 직접 연결이나 Vercel AI Gateway로 자동 우회하지 않습니다. 초기 설정에서는 AI를 호출하지 않고, 투자 시작 후 가드 대응·매매 상담에서 사용합니다. 각 답변에 실제 연결 또는 규칙 기반 대체 안내의 이유를 표시합니다.

투자 중 AI는 현재 포트폴리오·기본 가드 근거·최근 대화 12개와 현재 공개 사실을 바탕으로 대응과 비중 조정을 상담합니다. 사용자 조건은 새로 만들지 않습니다. 설명과 제안을 서버에서 검증하고 별도 근거 검토를 거칩니다. 실제 식별자·URL·미래 사건과 미확정 시세는 공개하지 않습니다. 질문이나 초안 적용만으로 주문하지 않습니다. 자세한 설정은 [OpenRouter 대화 연결](docs/OpenRouter_대화_연결.md)을 확인하세요.

초기 설정은 **직접 성향 선택 → 직접 코인·비율 설정 → 전체 확인·승인**으로 진행합니다. 진행 중인 예전 게임도 다음 요청에서 사용자 조건을 중단하고 기본 가드로 전환하며 거래·잔고·대기 주문·정지 상태를 보존합니다. [기본 가드 복원과 초기 설정 간소화](docs/기본가드_복원.md)

종목 이름은 **Asterra·Velora·Nexora·Lumera**라는 영문 가명입니다. 기존 대화·판단·체결 기록도 같은 이름으로 표시합니다. **자산 살펴보기 → 종목 선택**에서 거래별 체결가·수량·금액·수수료·매도 실현손익과 누적 손익을 확인할 수 있습니다. [영문 가명과 설명부터 시작하는 자산 상담](docs/영문가명과_자산설명_상담.md) · [종목별 거래 내역](docs/가명과_종목별_거래내역.md)

## 게임·체결 규칙

- 기간: **2022-11-07 00:00 KST~2026-08-05 23:59:59 KST**, 활성 재생 300초. 준비·대화·정지 중에는 게임 시간이 흐르지 않습니다.
- 초기 자금 100,000,000원에서 확정한 비중에 따라 초기 주문을 일괄 접수합니다. 대기 자금 100% 구성도 가능합니다.
- 서버가 시간·시세·수수료·잔고를 계산하고 Decimal 장부로 저장합니다.
- 매수 예산은 **수수료 포함 총지출 한도**, 매도 비율은 **보유 수량 기준**입니다. 매수·매도 수수료는 각각 0.05%입니다.
- 승인한 주문은 다음 일봉 시가에서 체결하므로 예상 수량·수령액과 다를 수 있습니다. 비중 조정은 매도 후 실제 확보한 자금 범위에서 매수합니다.
- 한 번에 하나의 주문 묶음을 접수하며 체결 전에 취소할 수 있습니다. 주문 예약금과 주문 가능 금액을 구분합니다.
- 대기 자금 이자는 과거 한국은행 기준금리 연동 **교육용 모델**이며 실제 예금 상품 금리가 아닙니다. 변경일 다음 날부터 적용하고 게임 경과 기간에 세전 단리로 적립해 종료 시 정산합니다. 주문 예약금과 미수이자에는 이자를 붙이지 않습니다.
- 예금·적금·채권의 차이를 안내하지만 미확정 E/F/G를 거래 상품으로 추가하지 않습니다. 주식·부동산 준비 중 화면과 새 투자 자료 공개 알림은 제외했습니다.
- 실제 식별자·원문 URL·미래 이벤트·미확정 일봉은 종료 전에 브라우저로 보내지 않습니다. 차트에는 완료된 일봉만 표시합니다.
- 장기 연결 중단은 게임 날짜를 건너뛰지 않도록 정지합니다. V2의 기존 게임은 보존하며 V3는 별도 브라우저 세션 키를 사용합니다.

원본 업비트 일봉 4종의 자산별 1,592행을 검증해 사용합니다. 시세 원본·정규화 CSV·세션 DB·인증정보는 Git에 넣지 않습니다. ZIP·README_V2.md·source_index.csv·archive는 보존합니다.

## Windows 로컬 실행·검증

`RUN_ERU_AI.cmd` 실행 후 [로컬 앱](http://127.0.0.1:8000)을 엽니다. 새 PC는 `SETUP_ERU_AI.cmd`, 종료는 `STOP_ERU_AI.cmd`를 사용합니다.

프론트엔드 의존성과 빌드는 로컬 캐시를 사용하는 `scripts/BUILD.ps1`로 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/BUILD.ps1
& "$env:LOCALAPPDATA\ERU-AI\alpha-v1-venv\Scripts\python.exe" -m pytest tests -q
Push-Location archive/ERU_AI_Investment_Simulator_V2
& "$env:LOCALAPPDATA\ERU-AI\alpha-v1-venv\Scripts\python.exe" -m unittest discover -s tests -v
Pop-Location
```

이메일 인증과 계정별 기록의 브라우저 검증은 `scripts/account_smoke.cjs`입니다. 로컬 QA 메일 공급자에서 로그인 필수·쿠키·두 계정 격리·다른 브라우저의 초안 복원·이어하기·복기·로그아웃·320/390px를 확인합니다. 운영은 실제 Supabase 이메일 인증을 사용하며 인증 우회 경로가 없습니다. 예전 비회원 검증 스크립트는 당시 검증 기록으로 보존하며 운영 인증 후 재사용하려면 본인 인증 쿠키와 계정 소유 기록이 필요합니다. 원시 결과·세션·화면은 Git에서 제외한 `test-results/`에 저장합니다.
