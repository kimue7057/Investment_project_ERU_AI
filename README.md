# ERU AI · 비트코인 하락장 리스크 가드

[운영 앱 열기](https://eru-ai-investment-simulator.vercel.app)

**스플래시 → 이메일 전용 설정 → 투자금 입력 → 현금 확보 과정 → 대표 하락장 3개 비교 → 하락 구간 결과 → 현금 확보·하락장 대응 복기**를 제공하는 모의 시뮬레이터입니다.

모바일은 수치와 차트를 우선 배치합니다. 재생·복기에서는 하단 메뉴와 큰 고정 종료 버튼을 줄이고 차트와 조작 공간을 확보합니다. 복기 장면은 가로 목록과 이전·다음 버튼으로 선택하며 차트와 설명이 함께 바뀝니다. 기본 언어는 영어이며 **Settings → 한국어** 또는 상단 **EN** 버튼에서 전환합니다. 영어는 싱가포르 달러(SGD, S$), 한국어는 원화(KRW, ₩)로 입력·표시합니다. 투자금·차트·결과·복기·기록과 결과 메일에 같은 기준을 적용합니다. 언어 선택은 이 기기에 저장되고 기존 비교·기록과 수익률은 유지됩니다.

새로 접속했을 때 기본 투자금은 영어 **S$100,000**, 한국어 **1억 원**입니다. 금액을 직접 수정하기 전에는 언어에 맞는 기본값으로 전환하며, 직접 입력하거나 빠른 금액을 선택한 뒤에는 같은 원금을 환산 표시합니다. 새 비교의 입력 금액과 이전 비교의 원금은 분리하여 기존 기록을 복원해도 새 기본값이나 작성 중인 금액을 덮어쓰지 않습니다.

표시 환산율은 [ECB 2026-11-13 기준환율](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)의 EUR/KRW 1477.80과 EUR/SGD 1.4236을 교차 계산한 **S$1 ≈ 1,038.07원**으로 고정합니다. 실제 환전이나 과거 환율 수익을 계산하지 않습니다. SGD는 소수 둘째 자리로 입력하며 원화 기준 장부에는 센트 환산 후 Decimal 금액을 전달합니다. 기존 원금을 환산 표시한 채 그대로 제출하면 표시 반올림으로 원금이 바뀌지 않습니다.

앱 화면은 기기의 높이에 맞춰 고정하고 콘텐츠만 내부에서 스크롤합니다. 재생은 날짜·두 계좌 수치·차트·플레이어를 같은 화면에 배치합니다. 데스크톱은 최대 1280px의 두 열로 확장해 차트와 상세 정보를 나란히 보여줍니다. 스플래시는 원본 로고로 제작한 4.8초 MP4를 접속·새로고침 시 재생합니다. 이전 탭의 시청 여부로 생략하지 않습니다. 설정의 다시 보기 메뉴는 제공하지 않습니다. 자동 재생 제한이나 영상 오류 때는 로고 화면을 표시한 뒤 진입하고, 모션 감소 설정에서는 정적인 인트로를 표시합니다.

- 새 비교는 `btc-bear-2` 버전입니다. 이전 `btc-guard-1` 전체 사이클 기록은 당시 엔진으로 계속 열며 조용히 새 구간으로 재계산하지 않습니다.
- 대표 하락장은 각 원래 사이클에서 BTC 종가의 최대 고점→저점 하락 구간을 사후 선정했습니다. 기간은 **2017-12-16~2018-12-15**, **2021-11-08~2022-11-21**, **2025-10-06~2026-02-05**입니다. 날짜를 사전 예측한 결과가 아닙니다.
- 각 구간 앞에는 원래 첫 매수부터 현금을 확보한 사전 운용 과정을 보여줍니다. 사전 운용 시작은 각각 2016-07-01, 2020-05-01, 2023-07-01입니다. 총 재생은 300초이며 각 구간의 30%는 사전 운용, 70%는 하락장 비교에 배정합니다.
- **하락 시작일 종가에서 두 계좌를 입력 금액으로 각각 정규화**합니다. 가드는 기존 BTC·현금 비중을 이어받습니다. 정규화를 위한 새 매매나 이중 수수료는 없으며, 이전 수익을 하락장 손익에 합산하지 않습니다. 고점에서 BTC 100%로 새로 출발한 결과가 아닙니다. 두 단계의 차트를 연결해 자산이 갑자기 감소한 것처럼 표시하지 않습니다.
- 단순 보유와 가드의 기간 수익률·종료 자산·최대 낙폭·회복 필요 상승률을 해당 하락 구간만으로 계산합니다. 비교 금액 1억 원에서 가드 손실률은 각각 약 -55.1%, -29.0%, -17.4%이며, 단순 보유는 -83.8%, -76.7%, -49.7%입니다.
- 같은 시작 BTC·현금 비중을 추가 매매 없이 유지한 **비중 고정 계좌**를 함께 표시합니다. 기존 현금과 추가 매매 효과를 구분하며, 2차 구간처럼 비중 고정 계좌가 가드보다 유리한 결과도 그대로 보여줍니다. 별도 펼침 영역에서는 기존 전체 사이클 종료 자산을 확인합니다.
- 복기는 **현금 확보 / 하락장 대응** 두 구간으로 전환합니다. 판단일·다음 일봉 시가 체결일·거래금액·수수료·현금·비중·당시 평가액을 각 단계 기준으로 표시합니다. 장면은 수익순으로 선정하지 않습니다.
- 원본 Coinbase BTC-USD 공식 일봉 3,683개와 불변 Decimal 운용 장부를 재사용합니다. 기존 매매 규칙·체결·시세·비공개 구현의 해시를 변경하지 않습니다. 확정 일봉으로 판단하고 다음 일봉 시가에 체결하며 편도 수수료는 0.05%입니다.
- 환율 변동·현금 이자·슬리피지는 미반영합니다. 기록은 이 브라우저 방문자 쿠키로 구분하며 이메일 계정 인증이나 다른 기기 자동 연결은 없습니다. 아직 진행하지 않은 일봉·대응·하락 시작 현금 비중을 미리 공개하지 않습니다.

## 수치·차트 중심 화면

- 차트는 컨테이너의 실제 너비로 다시 그립니다. 820px SVG를 축소하지 않으며, 모바일 차트 높이는 화면에 따라 215~270px입니다. 축 글자·선 두께·44px 마커 선택 영역은 표시 크기에 맞춰 유지합니다.
- 현금 확보 단계는 공개된 일별 BTC·현금 비중을 사용합니다. 중간 비중을 추정하거나 장면 사이를 임의의 매매로 채우지 않습니다. 이전 전체 사이클 기록에 비중 이력이 없는 경우에는 기존 자산 차트를 사용합니다.
- 일시정지한 재생과 결과 화면에서는 날짜 슬라이더 또는 차트 위치를 눌러 공개된 실제 일봉 값을 탐색할 수 있습니다. 계산 결과·재생 시계·주문에는 영향을 주지 않습니다.
- 결과는 종료 잔액 차이, 기간별 자산 곡선과 두 계좌 잔액을 먼저 보여줍니다. 수수료·최대 낙폭·전체 사이클 등은 상세 영역으로 정리하며, 비중 고정 비교는 계속 확인할 수 있습니다. 이메일 발송 상태는 결과 하단에 있습니다.
- 복기 차트에는 최초 대응 종류별 장면·마지막 장면·선택 장면을 합쳐 최대 5개의 마커만 표시합니다. 전체 주요 장면은 목록에 남깁니다. 장면 선택 시 세로 자동 스크롤을 하지 않으며, 선택일 수치·커서·현금·BTC 비중이 함께 갱신됩니다.

## 결과 메일

처음 접속하면 스플래시 다음에 이메일 전용 화면을 표시합니다. 이메일과 결과·회사 소개 수신 동의를 저장한 뒤 별도 투자금 설정 화면으로 넘어갑니다. 투자금 화면에는 이메일 입력을 섞지 않습니다. 설정의 **보고서 수신 설정 → 수신 이메일 변경**에서 새 주소와 동의를 저장할 수 있습니다. 인증번호는 받지 않습니다. 비교가 끝나면 서버가 실제 종료 결과와 ERUTY 회사 소개를 Resend로 자동 발송합니다. 자동 재생 완료와 결과 바로 보기 모두 같은 발송 경로를 사용합니다. 본문에는 대표 하락장 3개의 자산 변화 그래프·종료 자산·최대 낙폭과 사전 현금 확보 내역·시작 현금 비중·비중 고정 비교·대표 대응을 넣습니다. 앱과 같은 어두운 배경과 금빛 강조를 사용하며, 상세 결과·전체 복기 PDF와 회사 소개 PDF를 함께 첨부합니다. 상세 복기에는 현금 확보와 하락장 대응을 분리하고 각 단계의 그래프·주요 장면·전체 대응 내역·정규화 기준을 담습니다. 영어는 SGD, 한국어는 KRW 보고서를 보냅니다.

운영 환경은 Resend에서 인증된 `eruty.co.kr` 도메인의 `ERU AI RiskGuard <noreply@eruty.co.kr>`를 발신 주소로 사용합니다. `RESEND_API_KEY`와 `RESEND_FROM_EMAIL`은 서버의 Vercel Production 환경에만 등록하며, 변경 후에는 운영 배포를 다시 실행해야 합니다. 같은 결과·수신자·보고서 버전에 대한 중복 요청은 재발송하지 않습니다. 이전 기본 메일을 받은 경우 기존 전체 사이클 상세 보고서 버전(`review-2`)을 한 번 요청할 수 있습니다. 이미지 그래프는 외부 주소로 공개하지 않고 메일 내부 CID 첨부로 전달합니다. 수신 주소·동의는 방문자 쿠키에 연결된 서버의 이메일 설정으로 보관합니다. 새 비교는 저장된 설정을 사용하며, 보고서 언어는 각 비교를 시작할 때 정합니다. 브라우저 저장소에는 이메일을 저장하지 않습니다. 공개 응답에는 마스킹한 주소와 발송 상태만 제공합니다. 발송 접수 후 해당 결과의 원문 이메일은 제거하고, 이후 비교에 사용할 이메일 설정은 유지합니다. 변경한 주소는 새 비교와 아직 발송하지 않은 보고서부터 적용합니다. 이미 발송했거나 발송 처리 중인 보고서는 기존 주소를 유지하여 중복 발송을 막습니다. 결과 화면에서는 자동 발송 상태를 확인하고, 실패한 경우에만 등록한 주소로 재시도할 수 있습니다. 새 하락장 보고서는 `bear-review-3`로 구분하며 기존 기록에는 `review-2`를 유지합니다. 이미 발송된 보고서는 새로고침으로 중복 발송하지 않습니다. 이전 이메일 미등록 기록의 결과·복기는 유지되며, 새로운 이메일 설정은 첫 접속 시 한 번 등록하고 이후 이 브라우저에서 재사용합니다. 자동 보고서는 새 비교부터 적용합니다. 화면의 ‘발송 접수’는 공급자 접수 상태이며 받은편지함 배달 완료와 구분합니다.

## 개발·검증

프론트엔드 의존성과 빌드는 로컬 캐시를 사용하는 `scripts/BUILD.ps1`로 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/BUILD.ps1
& "$env:LOCALAPPDATA\ERU-AI\alpha-v1-venv\Scripts\python.exe" -m pytest tests -q
Push-Location archive/ERU_AI_Investment_Simulator_V2
& "$env:LOCALAPPDATA\ERU-AI\alpha-v1-venv\Scripts\python.exe" -m unittest discover -s tests -v
Pop-Location
```

데이터·계산·공개 경계·메일 상태·배포 원본 보관은 [비트코인 자동 비교 V1 구현 기록](docs/비트코인_자동비교_V1.md)을 확인하세요. 시세 원본·정규화 CSV·DB·인증정보는 커밋하지 않습니다.
