# 비트코인 자동 비교 V1

## 사용자 요청과 운영본 보관

2026-11-15 요청에 따라 새 메인을 비트코인 단독 비교로 전환했습니다. 기존 운영본의 소스는 `codex/archive-main-before-bitcoin-20261115` 브랜치와 `ef21d3d`에 보관합니다. 기존 세션을 삭제하거나 새 방문자 기록에 자동 연결하지 않습니다.

진입 전 이메일 인증을 제거했습니다. 모바일 첫 진입에는 2.6초의 로고 스플래시 애니메이션을 제공합니다. 건너뛰기와 동작 줄이기 설정을 지원하고, 같은 탭에서 반복 표시하지 않습니다. 실제 MP4 영상을 자동 다운로드하지 않습니다.

## 실제 계산

- 입력 금액: 1만 원~100억 원, 기본 1억 원. 총 기본 재생은 300초이며 1/4/8배속을 지원합니다.
- 원본 구간의 월 단위 표기를 월 첫날~마지막 날로 해석했습니다: 2016-07-01~2020-04-30, 2020-05-01~2023-06-30, 2023-07-01~2026-05-31.
- 두 계좌 모두 같은 자금으로 BTC 100%에서 출발하며 각각 초기 매수 수수료를 반영합니다. ETH와 초기 현금 35%를 그대로 가져오지 않습니다.
- 데이터는 Coinbase Exchange의 BTC-USD 공식 일봉입니다. 2016-05-01~2026-05-31의 3,683개 일봉을 연속성·중복·OHLC·해시 기준으로 검증했습니다. 2016년 5~6월은 지표 준비 구간입니다.
- 제공된 엑셀의 판정·분할·국면 규칙을 서버에서 재계산합니다. 상세 지표와 수식은 브라우저에 보내지 않습니다.
- 완료된 일봉의 현재·이전 정보를 함께 사용해 신호를 판정합니다. 완료 일봉에서 판단한 뒤 다음 일봉 시가로 체결합니다. 최종 일봉의 신호는 구간 밖에서 체결하지 않습니다.
- 월별 구분과 국면 해제 표현을 실행 가능한 규칙으로 명시한 버전입니다. 상세 기준은 비공개 구현에 보관합니다.
- 자금은 Decimal, 시간은 서버에서 계산합니다. 클라이언트는 시세·수익·진행률·주문 결과를 제출할 수 없습니다.
- 원화 입력액에 USD 가격의 상대 변화율을 적용한 노출 장부입니다. 환율 변동·현금 이자·슬리피지와 최소 주문·호가 영향은 미반영합니다. 내부 노출 단위를 실제 BTC 개수로 표시하지 않습니다.
- `model_version`과 시세 지문을 세션에 고정합니다. 다른 버전에서 과거 기록을 조용히 재계산하지 않습니다.

## 결과 해석

단순 보유 대비 최종 자산 차이와 각 계좌 자체 고점 대비 최대 낙폭을 함께 보여줍니다. 세 구간 모두 이번 계산에서 가드의 낙폭은 작지만 최종 자산은 단순 보유보다 적었습니다. 이를 숨기거나 리플렛의 혼합 포트폴리오 수치를 BTC 성과로 복사하지 않습니다.

최대 낙폭은 일별 종가 평가 기준입니다. 두 계좌의 자체 고점 날짜가 다를 수 있으므로 낙폭 차이(%p)를 보호한 원화 금액으로 단정하지 않습니다. 회복 필요 상승률은 `1/(1+최대낙폭)-1`이며 이후 BTC 수익을 예측하는 값이 아닙니다.

주요 장면은 수익 크기 대신 대응 종류·시간 순서로 최대 20개를 선정합니다. 전체 매도·매수·보류 기록도 종료 후 확인합니다. 체결일, 판단일, 수수료, 직후 현금과 비중, 해당 일봉 평가액을 구분합니다.

## 공개 경계와 기록

새 경로는 `/api/bitcoin/*`입니다. 기존 `/api/sessions/*`와 계정 인증 경계는 유지합니다. 방문자마다 별도 무작위 HttpOnly·Secure·SameSite=Lax 쿠키를 발급하고 해시만 서버에 저장합니다. 세션 ID만 알아도 다른 방문자의 결과·재생·메일에 접근할 수 없습니다.

진행 시점 이후의 시세·대응과 미래 사이클의 수치는 반환하지 않습니다. 재생 종료 또는 명시적 결과 바로 보기를 실행한 뒤 전체 결과를 반환합니다. 완료된 구간만 되돌아볼 수 있으며 재생 위치를 임의의 클라이언트 값으로 덮어쓰지 않습니다. 15초 이상 통신이 끊기면 정지하고 마지막 표시 위치를 보존합니다.

Supabase의 기존 서버 전용 JSON 저장소를 재사용합니다. 새 모드는 `bitcoin_v1`이며 기존 계정·게임과 분리됩니다. 브라우저 기록 목록에는 ID·금액·상태·진행률·생성 시각만 포함합니다.

## 메일: 실제 발송 연결

2026-11-16 사용자의 요청으로 기존 발송 보류를 해제했습니다. Resend에서 `eruty.co.kr` 도메인의 인증 상태를 확인하고, Vercel Production의 `RESEND_FROM_EMAIL`에 `ERU AI RiskGuard <noreply@eruty.co.kr>`를 등록했습니다. 기존 `RESEND_API_KEY`를 재사용하며 인증정보를 코드나 브라우저에 전달하지 않습니다. 환경 변수 변경은 새 운영 배포부터 적용됩니다.

결과 화면에서 주소와 명시적 동의를 입력해 해당 결과와 ERUTY 회사 소개를 한 번 요청합니다. 가입·인증번호·마케팅 구독은 없습니다. 본문은 서버의 실제 종료 결과로 만들고 회사 소개 PDF를 첨부합니다. 선택 언어에 따라 영어·SGD 또는 한국어·KRW 보고서를 구성하며 PDF는 원본 한국어 자료를 유지합니다. 클라이언트가 제목·본문·성과·첨부·수신 목록을 조작할 수 없습니다.

이메일은 요청 처리에만 사용하며 세션에는 수신자 해시와 접수 기록을 둡니다. 중복 요청은 서버 수신 기록과 Resend idempotency key로 막고, 처리 중 lease와 방문자·수신자·일별 발송 한도를 적용합니다. 공급자 오류의 본문·인증정보는 응답하지 않습니다. Resend의 요청 접수를 실제 받은편지함 배달 완료로 표현하지 않습니다.

## 배포 데이터

원본·정규화 CSV·bootstrap gzip·상세 계산 구현은 Git에서 제외합니다. 비공개 구현은 `data/private/bitcoin_engine_impl.py`에 보관하고, 공개 로더는 검토된 SHA-256과 버전이 일치할 때만 해당 모듈을 사용합니다. 최초 배포의 비공개 소스로만 bootstrap을 전달하고, 기존 Supabase 서버 전용 세션 테이블에 `bitcoin_market_bundle` 레코드로 저장합니다. 이후 Git 배포에서는 시세와 구현을 각각 해시 검증 후 빌드합니다. 기존 `alpha-v1` 시세 원본을 덮어쓰지 않고 새 DB나 유료 서비스를 만들지 않습니다.

## 검증

기존 pytest·archive unittest·프론트엔드 타입 검사/테스트/빌드와 함께 BTC 다음 시가 체결, Decimal 장부 정합성, 미래 일봉 변경에 대한 과거 불변성, 공개 응답의 미래 정보 차단, 낙폭 극점 보존, 방문자 격리, 서버 재생과 비활성 정지, 결과 위조 거부, 메일 중복 방지·공급자 오류·동의를 검증합니다.

실제 시세로 브라우저의 인증 없는 진입·스플래시·금액 검증·재생·세 사이클 결과·전체 대응·모바일·새로고침 복원을 확인합니다. 이메일 테스트는 공급자 HTTP 대체를 사용하며 실제 수신함 검증은 보류 상태입니다.
