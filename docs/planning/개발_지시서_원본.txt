## 3. 서비스 목표

이 서비스는 실제 과거 금융시장 데이터를 이용해 사용자가 투자 전략을 직접 실험하는 **5분 투자 시뮬레이션 게임**입니다.

사용자에게 가상의 초기 투자금 1억 원을 지급합니다.

사용자는 코인, 주식, 부동산 등 투자상품 정보를 조사하고 자신만의 포트폴리오를 구성합니다.

이후 과거 시장 데이터가 5분 동안 빠르게 재생되며, 사용자는 시장 상황을 관찰하다가 언제든 일시정지하여 매수·매도·비중 조정을 진행합니다.

AI 리스크 가드는 기본적으로 시장과 포트폴리오를 분석하여 투자 위험 및 매매 시점을 제안합니다.

최종적으로 사용자가 정해진 투자기간 동안 자산을 얼마나 효과적으로 성장시키고 위험을 관리했는지 평가합니다.

### 기본 게임 조건

| 항목 | 내용 |
|---|---|
| 투자 시작일 | 2022년 11월 7일 |
| 투자 종료일 | 2026년 8월 5일 |

현재 게임기간은 정확한 지정 날짜를 기준으로 구현하며, 임의로 5년으로 변경하지 마세요.

## 4. 투자상품 구조

게임에서는 실제 자산의 가격 데이터를 사용하지만, 투자상품의 이름은 가명으로 표시합니다.

| 게임 표시 | 실제 투자상품 |
|---|---|
| 현금 | KRW |
| 코인 A | Bitcoin / BTC |
| 코인 B | Ethereum / ETH |
| 코인 C | Solana / SOL |
| 코인 D | Dogecoin / DOGE |
| 주식 E | 국내 개별 상장주식, 확정 필요 |
| 주식 F | 상장 ETF, 확정 필요 |
| 부동산 G | 리츠 또는 부동산 ETF, 확정 필요 |

주식 E/F와 부동산 G는 실제 상품이 아직 최종 확정되지 않았습니다.

기존 기획에서 검토한 삼성전자, 미국 나스닥100 ETF, 리츠·부동산 ETF 등은 후보일 뿐입니다.

임의로 최종 상품을 확정하거나 가상의 가격을 만들어 넣지 마세요.

**Alpha V1은 현금과 코인 A~D를 우선 완성하고, 추후 주식과 부동산을 같은 투자 엔진에 연결할 수 있도록 확장 가능한 구조로 개발합니다.**

## 6. 투자상품 정보 제공

사용자는 투자상품 이름만 보고 투자하는 것이 아닙니다.

반드시 포트폴리오를 구성하기 전에 자산별 정보를 확인할 수 있어야 합니다.

### 코인 A~D

- 기술 및 프로젝트 개요
- 백서 또는 공식 기술문서 요약
- 네트워크 특징
- 발행 및 공급 구조
- 주요 위험 요소
- 당시까지 공개된 기술 변화 및 사건

정식 백서가 없는 자산은 임의의 백서를 생성하지 말고 공식 기술자료로 구분하세요.

### 주식 E/F

- 업종 및 주요 사업
- 기업 실적 또는 ETF 추종 지수
- 투자상품 구조
- 재무정보·운용정보
- 당시까지 확인 가능한 주요 발표
- 시장 및 투자 위험

### 부동산 G

- 기초 부동산 유형
- 보유 또는 편입 자산
- 임대·분배 수익구조
- 금리·공실·차입 위험
- 운용 및 거래 특성

### 매우 중요한 정보 공개 규칙

**게임 현재 날짜보다 미래에 공개된 정보는 절대로 사용자에게 보여주면 안 됩니다.**

예를 들어 게임 날짜가 2022년 11월 7일이라면, 2023년에 발표된 실적이나 기술자료를 보여줘서는 안 됩니다.

자료 공개 기준은 회계 기준일이 아니라 실제 공시·발표·배포 일시입니다.

정보 공개 제어는 반드시 서버에서 처리하세요.

미래 데이터 전체를 브라우저에 전달한 후 화면에서만 숨기는 구현은 금지합니다.

실제 종목명·티커·로고·원문 URL 등 가명의 정체를 노출할 수 있는 정보도 게임 종료 전까지 사용자에게 전달하지 마세요.

- KRW-BTC

일봉 OHLCV 데이터를 확보하고 다음 항목을 검사하세요.

- 실제 최초 거래 가능 날짜
- 데이터 시작일 및 종료일
- 일별 누락 여부
- 타임존 및 거래소 캔들 기준
- 시가·고가·저가·종가의 정합성
- 거래량
- 중복 데이터
- 비정상 가격

수집한 데이터는 원본과 정규화 데이터를 구분하여 저장하세요.

과거 데이터 조회에 실패하면 실패 원인을 기록하고, 다른 공식적인 자료 제공 경로를 검토하세요.

**실제 데이터를 수집하지 못한 경우 가상의 시세를 실제 데이터인 것처럼 사용하지 마세요.**

서비스 공개 전 시세 및 기술문서의 이용약관, 상업적 재사용, 재배포 제한도 확인해야 합니다.

## 8. 시장 재생 엔진

전체 시장기간을 300초에 맞춰 재생하는 엔진을 구현하세요.

필요한 기능은 다음과 같습니다.

- 현재 시뮬레이션 날짜 관리
- 300초 압축 재생
- 재생·일시정지
- 현재 시점까지의 가격 차트
- 현재 보유 수량 계산
- 현재 포트폴리오 평가금액 계산
- 실현손익 및 미실현손익
- 현금 잔고 계산
- 게임 종료 판정
- 재도전 시 초기화

일시정지 시에는 게임 속 시장시간이 정지되어야 합니다.

게임에서 의사결정을 하는 시간은 재생 시간과 별도로 관리할 수 있도록 설계하세요.

### 미래정보 누출 방지

매매 신호는 해당 날짜에 확정된 데이터만 활용해야 합니다.

주봉 기술지표에서는 아직 종료되지 않은 주의 최종 종가를 미리 사용하는 행위를 금지합니다.

매수·매도 신호가 확정된 이후의 첫 체결 가능 가격 등 일관된 거래 체결 규칙을 정의하고 적용하세요.

미래 가격을 이용해 현재의 AI 매매 판단을 생성해서도 안 됩니다.

## 9. 매매 및 리밸런싱 엔진

사용자는 게임 도중 언제든 매매할 수 있어야 합니다.

필요한 기능:

- 자산별 매수
- 자산별 매도
- 매수·매도 금액 입력
- 보유 자산의 일정 비율 매도
- 가용 현금의 일정 비율 매수
- 목표 포트폴리오 비중 수정
- 리밸런싱 실행
- 주문 완료 후 보유량 및 현금 잔고 갱신
- 거래 내역 저장
- 거래 수수료 반영

보유하지 않은 수량을 매도하거나, 보유 현금을 초과한 매수가 실행되지 않도록 처리하세요.

목표 비중을 수정하는 행동과 실제 주문을 실행하는 행동은 구분합니다.

초기 1억 원 외에 임의의 현금이 추가되지 않도록 합니다.

## 10. AI 리스크 가드

AI 리스크 가드는 사용자가 선택하거나 조건을 설정하는 기능이 아닙니다.

**ERU AI가 내부적으로 제공하는 기본 투자분석 기능입니다.**

다음 기능을 구현할 수 있도록 설계하세요.

- 기술적 매매 신호 분석
- 매수·매도 검토 시점 제안
- 분할매매 비율 제안
- 포트폴리오 집중 위험 분석
- 변동성 및 손실 위험 분석
- 현금 비중 관리 제안
- 투자 위험 알림
- 사용자 선택 기록

기획에서 참고한 분석 지표로는 주봉 볼린저 밴드, RSI, 이동평균, 포트폴리오 위험 지표 등이 있습니다.

다만 해당 조건의 세부 수치, 조합, 내부 판단 로직을 사용자가 선택하거나 변경하는 화면을 구현하지 마세요.

사용자에게는 AI의 분석 결과, 판단 근거 요약, 제안 행동을 보여줍니다.

사용자는 다음 행동을 선택할 수 있습니다.

- 제안 수용
- 실제 매매 비율 수정
- 제안 무시

AI의 제안은 수익을 보장하지 않으며, 최종 매매 결정은 사용자에게 있습니다.

Alpha V1은 재현 가능한 규칙 기반 신호 엔진을 먼저 구현하고, AI 자연어 설명 기능은 분리된 구조로 개발해도 됩니다.

## 11. UI / UX 개발

기존 Figma 디자인을 기준으로 React 웹 UI를 구현하세요.

기본 디자인 방향은 다음과 같습니다.

- 전문적인 금융투자 서비스
- 다크 테마
- 간결하고 가독성 높은 데이터 표시
- 차트 중심의 시뮬레이션 화면
- 우측 자산 현황 및 투자 조작 패널
- 중요한 매매 시점에 팝업 제공
- 사용자 의사결정을 방해하지 않는 AI 알림

실제 개발에서는 기존 18개 디자인 화면을 참조하세요.

다만 기존 디자인은 UI 시안이므로 실제 시세, 잔고, 수익률, 이벤트 정보로 교체해야 합니다.

Figma에 사용된 예시 가격과 수익률을 실제 데이터로 오인하여 하드코딩하지 마세요.

Figma 접근이 불가능하다면 먼저 그 사실을 보고하고, 기존 파일이나 스크린샷 등 대체 가능한 디자인 자료를 확인하세요.

## 14. GitHub 연결 및 운영

사용자가 생성한 기존 저장소를 사용합니다.

https://github.com/kimue7057/Investment_project_ERU_AI

먼저 다음을 검사하세요.

- 현재 디렉터리가 Git 저장소인지
- `.git` 폴더가 있는지
- `origin` 원격 저장소가 정확한지
- 기본 브랜치가 무엇인지
- 기존 파일과 변경사항이 무엇인지

이미 Git 저장소라면 재초기화하지 마세요.

아직 연결되지 않았다면 기존 원격 저장소 내용과 로컬 파일을 보존하면서 안전하게 연결하세요.

필요하다면 별도 개발 브랜치를 사용하세요.

작업 후 테스트를 진행하고, 기능 단위로 Git 커밋 및 푸시를 수행하세요.

Force push, 기존 Git 이력 삭제, 기존 파일 강제 덮어쓰기는 금지합니다.

또한 프로젝트 폴더가 Google Drive 동기화 경로에 있으므로 `.git` 내부 데이터의 동기화 충돌 위험을 확인하세요.

API 키, 인증정보, 재배포가 허용되지 않은 원본 데이터, 대용량 시세 원본 등은 `.gitignore` 또는 별도 저장 규칙으로 관리하세요.

## 16. 테스트와 완료 기준

Alpha V1은 다음 조건을 충족해야 합니다.

1. 사용자가 로컬 웹사이트에 접속할 수 있다.
2. 실제 과거 시장 데이터가 검증되어 있다.
3. 초기 1억 원을 원하는 비율로 투자할 수 있다.
4. 시장을 300초에 압축하여 재생할 수 있다.
5. 언제든 일시정지 및 재개할 수 있다.
6. 매수·매도·비중 조정이 정확하게 반영된다.
7. 현재 게임 날짜 이후의 데이터가 사용자에게 노출되지 않는다.
8. 최종 평가자산과 수익률이 정확하게 계산된다.
9. 처음부터 재도전할 수 있다.
10. 로컬 실행 방법과 테스트 결과가 문서화되어 있다.

테스트에 사용하는 인공 데이터는 테스트 전용으로 격리하고, 실제 플레이에서 역사적 데이터인 것처럼 표시하지 마세요.
