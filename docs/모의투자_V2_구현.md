# 모의투자 V2 구현 · 2026-10-20

Figma V2의 밝은 화면과 종목 중심 구조를 실제 React/Vite 앱에 적용했습니다. 종목 탐색·검색·관심 종목·차트·종목 정보·매수·수량 매도·주문 확인·대기/취소·체결 이력·보유 자산·최종 성과·정체 공개·재도전을 연결했습니다.

## 상태와 서버 경계

새 UI는 `POST /api/paper-sessions`로 별도 모의투자 세션을 만들고 `play`로 초기 주문 없이 현금 1억 원을 유지한 채 시작합니다. 브라우저 저장 키는 `eru-paper-session`입니다. 이전 Alpha 세션과 혼동하지 않습니다.

`mode: paper`에서는 자료 공개·위험 신호를 평가하거나 이에 따라 정지하지 않습니다. 공개 응답은 명시적 허용 필드로 만들고 `research`, `alerts`, `choices`, `targets`, `guard`를 보내지 않습니다. 이전 세션의 로컬/클라우드 호환 경로와 원본 자료는 보존했습니다.

서버 시간·Decimal 장부·다음 일봉 시가 체결·수수료 포함 매수 예산·실제 과거 CSV를 유지했습니다. 매도는 문자열 수량으로 정확한 소수 입력을 받고, 비율 버튼은 서버의 보유 수량 기준으로 계산합니다. 차트는 선택한 종목의 확정 일봉만 표시합니다.

Figma 시안과 달리 실제 앱의 매수 입력은 기존 장부와 동일하게 수수료 포함 총예산으로 표시합니다. 확인 화면에서 매수대금과 수수료를 나눠 보여줘 총예산을 두 번 차감하지 않습니다.

## 검증

- 백엔드 42개 테스트 통과: 기존 31개와 새 모의투자·정확한 수량 매도·자동 정지 제거·공개 경계·클라우드 복원·시간 체크포인트 재시도 회귀 테스트.
- archive의 기존 unittest 10개 통과.
- `scripts/BUILD.ps1`의 프론트엔드 타입 검사·테스트 2개·프로덕션 빌드 통과.
- 로컬 실제 브라우저에서 매수 주문 접수·취소·다음 시가 체결, 보유량의 25% 매도, 현금·수량 반영, 새로고침 복원, 검색과 390px 모바일을 확인했습니다. 브라우저 오류는 없었습니다.
- 온라인 배포 후 정식 공유 주소에서 같은 흐름과 실제 300초 종료를 추가 확인합니다. 원시 결과는 `test-results/paper-cloud-report.json`에 저장합니다.

첫 온라인 장기 검사에서 Blob 시간 체크포인트 쓰기에 일시적인 HTTP 400이 한 번 발생했습니다. 같은 저장 상태로 조건부 쓰기를 다시 확인했을 때는 성공했습니다. 사용자 주문을 재실행하지 않는 순수 시간 체크포인트에 한해 재조회·저장을 재시도하며, 주문·체결·정지 경계의 저장 실패는 그대로 알립니다. 연결 오류 표시는 다음 정상 조회에서 해제합니다. 중단된 검사는 같은 세션의 활성 재생 약 65.89초 지점에서 복원해 계속합니다.

초기 복원 조회가 503일 때도 저장된 세션 ID를 유지하고 다시 연결하도록 수정했습니다. 404일 때만 새 세션을 생성합니다. 브라우저 검사에서 복원 조회 한 번에만 503 응답을 주입하고 세션 ID·기존 거래 2건이 유지되는지 확인했습니다. 실제 가격 데이터는 변경하지 않았습니다.
