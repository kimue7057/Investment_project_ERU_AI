## 준비한 재발 방지 수정

이 수정은 로컬 검증을 마쳤으며 아직 운영에 배포하지 않았다.

- 준비·정지·종료 화면의 1.3초 반복 조회를 제거했다. 자산 차트가 바뀔 때 필요한 한 번의 읽기만 수행한다. 실행 중에는 응답을 받은 뒤 다음 조회를 예약해 겹치지 않는다.
- 연결 오류가 나면 간격을 늘리고 3회 연속 실패 뒤 자동 조회를 멈춘다. 사용자가 연결을 다시 확인할 수 있다.
- 첫 연결 실패 화면에 실제 오류와 재연결 동작을 표시한다. 실패한 새 게임 생성으로 기존 세션 ID를 덮어쓰지 않는다.
- 상태 점검은 비공개 저장소 읽기 가능 여부를 검사한다. 60초 동안 결과를 재사용하고 객체는 쓰지 않는다. 저장소가 막혔으면 `storage_unavailable`와 HTTP 503을 반환한다. 기존 점검은 저장소 객체가 생성돼 있기만 하면 ready라고 표시했다.
- 새 게임 저장 실패도 고정된 단계·HTTP 상태·안전한 오류 코드만 기록한다. 토큰·비공개 URL·제공업체 원문은 응답과 로그에 공개하지 않는다.

반복 조회는 사용량을 불필요하게 소비하는 코드상 문제이며, 이번 한도 초과의 정확한 사용량 구성은 운영 사용량 화면의 별도 확인이 필요하다.

## 복구 결정이 필요한 부분

기존 저장소를 계속 쓰려면 한도 정지 해제와 요금제 확인이 필요하다. 별도 DB로 전환하는 방법도 있으나 DB 준비·연결과 세션 저장 계층 변경이 필요하다. 기존 Blob 세션은 접근이 복구된 뒤 이관할 수 있으며, 지금은 보존한다.

시세 빌드 원본도 같은 비공개 Blob에 있으므로 현재 배포 방식의 새 빌드 역시 접근 복구가 필요하다. 서비스 복구와 배포 성공을 확인하기 전에는 완료로 보고하지 않는다.

## 사용자가 선택한 복구 방향

사용자는 별도 DB로 세션 저장소를 전환하기로 선택했다. Vercel Marketplace의 Neon 무료 요금제 free_v3, Singapore(sin1), 인증 기능 없음, 프로젝트 production/preview/development 연결을 요청했다. 계정 소유자의 약관 동의가 필요하다는 응답으로 중단됐고 DB는 아직 생성되지 않았다.

[Vercel Neon 약관 동의](https://vercel.com/eruty1/~/integrations/accept-terms/neon?source=cli) 후 같은 설치 인자로 이어간다. 부분 생성 여부를 확인하고 중복 DB를 만들지 않는다. 실제 DB와 자격증명이 준비된 뒤 저장 계층·조건부 쓰기·시세 빌드 원본 경로를 전환하고 운영에서 재검증한다. 기존 Blob 데이터는 삭제하지 않는다.

이후 사용자가 Supabase를 지정해 Neon 설치는 진행하지 않기로 변경했다. Supabase 연결을 확인했으며 조직은 KIMUE_PRIVATE 하나, 기존 프로젝트 4개는 다른 서비스 이름이다. 전용 프로젝트 생성 조직을 사용자에게 확인 중이며, 아직 Supabase 프로젝트를 만들거나 기존 프로젝트를 변경하지 않았다. Supabase의 SQL 기반 PostgreSQL을 사용하고, 새 프로젝트 비용은 확인 후 유료일 경우 먼저 승인받는다. 위 Neon 재시도 절차는 더 이상 적용하지 않는다.

## Supabase 조직 승인과 비용 확인

사용자는 KIMUE_PRIVATE에 ERU 전용 프로젝트 생성을 승인했다. 이후 `get_cost`가 새 프로젝트 비용을 월 US$10로 반환했다. 유료 생성은 명시적인 비용 동의를 요구하므로 해당 금액을 안내하고 답변을 기다리고 있다. 아직 프로젝트 생성·비용 확정·스키마 적용·운영 환경 변경·재배포는 수행하지 않았다.

생성과 독립적으로 서버 전용 `SupabaseSessions` 연결 코드를 준비했다. secret 키는 apikey 헤더에만 전송하며 브라우저로 보내지 않는다. production/preview/development별 세션을 구분하고, 수정은 기존 revision과 일치하는 행에만 적용해 동시 요청의 덮어쓰기를 막는다. 일부 Supabase 환경 변수만 설정된 경우 정지된 Blob으로 자동 전환하지 않는다. Supabase 저장소 단위 검증과 기존 클라우드 회귀 검증 19개가 통과했다. 이 검증은 HTTP 응답 픽스처이며 실제 Supabase DB 검증과 전체 배포 검증은 아직 남아 있다. 시세 빌드 원본의 이전과 전용 DB 스키마도 후속 작업이다.
