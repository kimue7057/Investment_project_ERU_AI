# Alpha V1 설계

## 신뢰 경계

브라우저는 별칭, 목표 비중, 주문 금액 또는 비율, 재생/정지, 제안 선택만 보냅니다. `Market`은 검증 보고의 SHA256와 실제 CSV를 대조해 로드하고, 해당 서버 시각까지 공개된 캔들과 연구 자료만 반환합니다. 프론트엔드는 전체 과거 시세나 정체 매핑 파일을 가져오지 않습니다. 정체는 finished 상태의 서버 응답에서만 추가됩니다.

FastAPI는 loopback에만 바인딩합니다. 브라우저 Origin/Host를 검사합니다. 정적 파일 경로는 frontend/dist만 마운트합니다. 이 설계는 로컬 내부 평가용으로, PC 소유자가 백엔드 파일이나 DB를 직접 읽는 것을 막는 보안 제품은 아닙니다.

## 재생

서버의 monotonic clock 차이를 활성 재생 시간에 더합니다. 시작~종료 타임스탬프 간 비율로 300초를 매핑합니다. 일별 시가와 실제 자료 공개 시점의 경계를 차례로 처리하므로 요청 간 여러 날짜가 흘러도 체결·평가·알림을 건너뛰지 않습니다. 자동 위험/자료 정지가 발생하면 그 경계에서 멈추고 아직 사용하지 않은 요청 시간은 진행시키지 않습니다. 클라이언트가 임의의 현재 날짜를 주입할 수 없습니다.

서버 재시작 시 저장된 running 게임을 paused로 복원합니다. 종료 후 주문·재시작을 거절합니다. 재도전은 별도 세션 UUID를 생성하며 이전 결과를 보존합니다.

## 장부

모든 수량·현금·원가·수수료·손익은 Decimal로 계산하고 SQLite JSON에는 문자열로 보존합니다. 표시용 응답에서만 금액/비율을 숫자로 변환합니다. 매수 원가는 수수료를 포함하며 매도는 이동평균 원가로 실현손익을 계산합니다. 입출금 API는 없습니다.

대기 주문은 한 번에 하나만 허용해 중복 지출과 중복 매도를 막습니다. 매수 예산/매도 수량을 주문 때 확정하고, 체결 가격은 다음 시가에서만 결정합니다. 목표 비중은 별도 저장하고 실제 리밸런싱 주문과 구분합니다.

리밸런싱은 체결 시각의 자산 평가액과 목표 비중을 사용해 `거래 후 순자산 + 모든 매도/매수 수수료 = 거래 전 자산`이 되는 순자산을 이분 탐색합니다. 매도 후 매수하므로 현금 0% 목표에서도 잔고를 초과하지 않습니다.

## 위험 분석

완료된 UTC 주의 종가로 주간 모멘텀을 계산합니다. 일봉은 확정 이후에만 사용합니다. 집중 위험·급락·과열에 분할 매도를 제안하고, 하락 강도가 높으며 현금 여력이 있으면 분할 매수를 검토합니다. 자동 일시정지는 내부 재알림 간격으로 제한합니다. AI는 별도 설정 없이 항상 실행되고 수용/수정/무시를 저장합니다. 자연어 생성기는 후속 확장 대상으로 분리했습니다.

## 저장 및 동시성

SQLite 세션은 매 요청 시 원자적으로 저장합니다. 단일 프로세스 RLock으로 같은 세션의 재생/주문 경쟁을 직렬화합니다. 여러 uvicorn workers를 쓰지 않습니다. 잘못된 주문도 이미 경과한 서버 재생 시간을 되돌리지 않습니다. 프론트엔드는 조회와 변경 요청을 직렬화해 주문 클릭이 정기 조회와 겹쳐도 사라지지 않게 합니다.
